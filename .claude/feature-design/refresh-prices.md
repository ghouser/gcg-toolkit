# refresh-prices: design

Spec: `claude-workspace/specs/gcg-toolkit/refresh-prices/spec.md` (PersonalClaude workspace)

## Approach
A new command `gundam_cards refresh-prices [--dry-run] [--force] [--allow-anomaly]` runs one function, `price_refresh.refresh_prices`, in the refresh-cards shape: **fetch**, **plan**, **write**. Fetch only fills the git-ignored raw cache (`tools/gundam_cards/data/raw/tcgcsv/<stamp>/`), so nothing in the dataset changes until the plan is checked and accepted; the one dataset write is a single atomic `add_snapshot` of the per-printing snapshot, so a refusal, failure or interruption leaves the dataset byte-identical and no tracked file is ever written.

**Fetch.** (1) If the newest recorded pull (the `pulled-at.txt` marker, written by a real `refresh-prices` run only, so saving a dump with `sync-tcgplayer` or a dry run does not count) is under 24 hours old and `--force` is not given: a real run fetches nothing, writes nothing and says so; a dry run, or a real run with `--allow-anomaly` (the way past a refusal), plans from that saved dump with no network. (2) Otherwise read `last-updated.txt` (one request); if that dump is already saved and `--force` is not given, use the saved one; else `fetch_dump` (about 58 requests, one at a time, `REQUEST_DELAY_S` apart, the toolkit User-Agent, tcgcsv only) and write the `pulled-at.txt` marker. A group that fails to fetch or parse, or an unreadable answer (`TcgcsvError`, `FetchError`), makes the run incomplete: it reports why and writes nothing. `sync-tcgplayer` becomes this fetch step alone (no snapshot, no pull marker: `refresh-prices` then prices from the saved dump after one `last-updated.txt` request); `reparse-tcgplayer` rebuilds the per-printing snapshots from the saved dumps, oldest first.

**Plan (pure).** `match_products(products, catalog, group_sets)` returns the matched rows plus a list of reports (product name, group, Number, reason).
- *Group to set* (design choice): a group maps to the set whose code equals its tcgcsv abbreviation, when `load_sets()` knows that code (GD01, ST01, SC01, EB01...); an abbreviation ending `_b` is Edition Beta and maps to `BETA` (the code the catalog gives those printings); a group whose name has "promo" is a promo group; any other group maps to no set. Why: it is the same fact the catalog already holds (a printing's `set_code` is Bandai's bracket code, else its package's set), it needs no table to maintain, and a new set is covered when `refresh` records it; an unknown group is reported rather than guessed.
- *Matching key*: `(set, card number, art tier)`. A printing's tier is its `alt_art_level` (link art carries level 1, so it matches as an alt art); a product's tier is the `+` / `++` on its rarity. A product matches when exactly one printing has its key and no other product has the same key. Reported, never matched: a product whose Number is not in the catalog, a product in a promo group, a group mapped to no set, an unrecognized rarity, a product matching zero or several printings, both products matching one printing, and a price row of an unrecognized kind (known kinds: `Normal`, `Holofoil`). A product with no Number (sealed) is counted, not reported. Several price rows of known kinds for one product: the cheapest, as today.
- *Snapshot row* (`PrintingPrice`): printing id, price in integer cents (`round(x * 100)`, once), product id, the product name and group abbreviation (so a Mass Entry line is unchanged), alt-art level (so the per-card price can be derived on read from the file alone), `fetched_at`.
- *Guard.* Against the newest per-printing snapshot: refuse when more than `MATCH_DROP_SHARE = 0.05` of its printings are not matched now, or when a group abbreviation that contributed rows to it is not in this pull; `--allow-anomaly` overrides. A price move never refuses. With no earlier snapshot the guard never refuses. Why 5%: a handful of printings drop out between pulls when a product is delisted, but a missing or reshaped group loses far more; 5% is the owner's "sharp fall" at a size a dropped group clearly exceeds, and the report gives both counts. Recorded in `docs/tuning.md`.
- *Moves*: the 10 largest absolute changes in cents between the newest snapshot and this plan (printing, old, new), reported in dry and real runs.

**Write.** `store.write_printing_prices` adds `printing_prices/<generated_at>.json` through `add_snapshot`: nothing is written when that UTC day already has one or the newest has the same prices (the content ignores `fetched_at`), and the run says so. Older per-card `prices/` files are never touched.

**Reads.** `store.load_prices()` keeps its type (a per-card `PriceFile`) and is what `price`, `buy`, `suggest`, `value` and `load_cards_with_prices` read: when a per-printing snapshot exists it is derived from the newest one (per card, the cheapest row with alt-art level 0, ties by product id, with the row's product, name, group and time), otherwise it is the newest per-card file as today. Nothing stores the derived price. `export` gives each printing its own row's price and date when a per-printing snapshot exists (no stopgap), else the stopgap as today.

**Request delay (design choice):** `REQUEST_DELAY_S = 1.0`. tcgcsv asks only for 100 ms and the existing sync used 0.5 s; a pull is at most one a day, so doubling the gap costs about a minute and is easier on a free community service.

## Files and interfaces
- `tools/gundam_cards/price_refresh.py` (new): `MATCH_DROP_SHARE`, `REQUEST_DELAY_S`, `GroupSets`, `group_sets(groups, set_codes)`, `match_products(...) -> Matched`, `plan_prices(...) -> PricePlan`, `refresh_prices(fetcher, raw_dir, ...) -> PriceReport`, `format_report`.
- `tools/gundam_cards/models.py`: `PrintingPrice`, `PrintingPriceFile` (schema 1).
- `tools/gundam_cards/store.py`: `write_printing_prices`, `load_printing_prices`, `load_printing_price_history`; `load_prices` derives per card when a per-printing snapshot exists.
- `tools/gundam_cards/export.py`: `build_export` takes the per-printing history and uses it when present.
- `tools/gundam_cards/tcgcsv.py`: parse keeps price kind issues; per-card `choose_prices` is replaced by the matching above.
- `tools/gundam_cards/cli.py`: `refresh-prices`; `sync-tcgplayer` fetch-only; `reparse-tcgplayer` builds per-printing snapshots.
- `shared/test_empty_dataset.py`: rows for the two new readers; `refresh-prices` listed as a network fetch.
- Docs: `tools/gundam_cards/design.md`, `docs/commands.md` (also the one-line note that an existing clone's saved Bandai pages in `tools/gundam_cards/data/raw/{cards,detail,lists,products}` can be copied into `$GCG_DATA_DIR/gundam_cards/pages/` to skip a full re-sync), `docs/tuning.md`, `docs/catalog-export.md` (the stopgap sentence goes), `docs/glossary.md`.

## Tests
All with small saved fixtures built in the tests, a fake fetcher, and the temp data folders of the root conftest; no network, no real dataset.
- AC-1: a product matches its printing by set, number and tier (base, `+`, `++`, link art as alt art; Edition Beta `_b`, SC01 and a reprint in another set each match their own printing); unmatched with a reason: Number not in catalog, promo group, unmapped group, unknown rarity, unknown price kind, zero printings, two printings, two products for one printing; a printing with no product has no row.
- AC-2: a real run writes one snapshot (cents, product id, as-of date, per printing id); a pull with equal prices and a second pull on the same UTC day add nothing and say so; the export gives each printing its own price and no card-level price, `schema_version` 1; `reparse-tcgplayer` rebuilds oldest first and a stored day adds nothing.
- AC-3: with a per-printing snapshot, `price`, `buy`, `suggest`, `value` readers give the cheapest non-alt-art price with the old per-card cents, product and name; alt-art-only card has none; before any per-printing snapshot the readers and export read the per-card file as today; old `prices/` files byte-identical after every command.
- AC-4: a failed or unparsable group, an unreadable listing and a `KeyboardInterrupt` during fetch leave the dataset byte-identical; the guard boundary (exactly 5% passes, just over refuses), a missing contributing group refuses, `--allow-anomaly` writes, a large price move does not refuse; the biggest moves are reported.
- AC-5: requests are sequential, at least `REQUEST_DELAY_S` apart, with the User-Agent and only to tcgcsv; a run under 24 hours after the previous pull fetches nothing and writes nothing, `--force` fetches; `--dry-run` plans, reports counts, reports and moves, writes no dataset file (the raw dump may be saved), and inside 24 hours plans from the saved dump with no network.

## Risks
- `sync-tcgplayer --force` re-saves a dump but records no pull, so it does not count toward the daily limit; only a real `refresh-prices` run does (accepted).
- Inside 24 hours, `--allow-anomaly` and a dry run read the saved dump; if it is unreadable or incomplete they stop with a message (rerun with `--force`) instead of downloading, so the 24-hour rule holds without `--force`. `--allow-anomaly` after a successful pull re-plans the same dump and adds nothing.
- Matching depends on the catalog's printing set codes: a printing without a `set_code` gets no price. The report lists unmatched products so a gap is visible; `refresh` fixes set codes.
- The per-card derivation must equal the old per-card choice on the same dump (the old rule picked the cheapest across all groups, the new one across matched non-alt printings): a product the old rule priced but matching rejects (unmapped group) now has no price. The report names those products; the owner sees them on the first dry run.
- Contracts made stricter: every reader of the per-card snapshot (`load_prices`, `prices_as_of`, `load_cards_with_prices`, `price`, `buy`, `suggest`, `value`, the dataset status, the export) goes through `load_prices`/`load_printing_prices`, found by search; `choose_prices` is gone; `write_prices` stays as the writer of the older per-card format only for tests that stand in for an old dataset (no command calls it).
