# toolkit-hardening: design

Spec: `claude-workspace/specs/gcg-toolkit/toolkit-hardening/spec.md` (PersonalClaude workspace)

## Approach
Three independent fixes, each small.

**Identifiers accept ASCII digits only (AC-1).** In Python `\d` matches any Unicode decimal digit (`٠`, `０`), so `CardNumber`, `PrintingId` and `PackageId` accept `ST٠١-٠٠١` and `６１６１０５` today. Their patterns in `shared/basetypes.py` change from `\d` to `[0-9]`, which is exactly what `docs/catalog-export.md` writes. `SetCode` already uses `[A-Z0-9]` (ASCII); it only gains fixture cases. Every file and page that carries an identifier is read through these types, so the fix is in one place.

**One setting moves the tools' raw and tracked folders (AC-2).** A new environment variable, `GCG_TOOL_DATA_DIR`, names a folder that stands in for the repository root for the cards and meta tools' data folders: the raw page caches are `<root>/tools/<tool>/data/raw/` and the tracked files `<root>/shared/data/<tool>/`. Unset, the root is the repository, so every folder is the same as today. Mirroring the repository layout keeps one rule for both tools and both kinds of folder, and the default is the same path arithmetic with a different root. `shared/dataset.py` (which already resolves `GCG_DATA_DIR`) gets `tool_data_root()`, resolved on every call. The import-time constants `RAW_DIR` and `OUT_DIR` of `tools/gundam_cards/store.py` and `tools/gundam_meta/store.py` are replaced by functions `raw_folder()` and `tracked_folder()`, and every default argument that held them becomes `None`, resolved in the body (the existing `out_dir or data_out_dir()` pattern). The CLIs call the functions when a command runs. The packages and collection tools keep their folders (out of scope).

The root `conftest.py` sets `GCG_TOOL_DATA_DIR` to a fresh temp folder for every test, like `GCG_DATA_DIR` (real-data tests, with `GCG_TEST_REAL_DATA=1`, see it as it is). So that tests that read the reviewed set list and restrictions keep working, that temp folder is seeded with a copy of the tracked `sets.json` and `restrictions.json` (the only tracked inputs); a test that writes there writes a copy, never the repository's file.

**Backstop against writes into the real `~/.gcg` (AC-2, amended).** A stray test run with `GCG_TEST_REAL_DATA=1` polluted the owner's real dataset, so redirecting locations is not enough on its own. `shared/dataset.py` gets `refuse_real_data_write(path)`: when the test suite is running (`pytest` is in `sys.modules`; production code never imports it) and the path resolves inside `Path.home() / ".gcg"` (the dataset, images, the catalog export), it raises `RealDataWrite` with a message naming the path and the reason. Every file writer calls it first, before creating a folder or a temp file, so nothing is written: the three store `write_atomic`s (`shared/dataset.py`, `tools/gundam_cards/store.py`, `tools/gundam_meta/store.py`; the packages and collection stores reuse the meta one) and the fetcher's cache write (`shared/fetch.py`). A check at the writers, not in `conftest.py`, also holds for a test that forgot to redirect a location or ran with real data. Outside a test run it does nothing. No code in this repository writes images today; a writer under `~/.gcg/images` would go through these same writers or the fetcher.

**A rebuild never writes `sets.json` (AC-3).** `sync --only sets`, `sync`, `reparse` and `refetch` (which reparses) today rebuild `sets.json` from Bandai and overwrite it; `refresh` reads it only. After this change none of them writes it, and `store.write_sets` is removed so no code path can. What Bandai lists goes through two pure functions in `sets.py`, shared by the refresh and the CLI rebuilds:
- `propose_sets(tracked, stored, bandai)`: the provisional record after a rebuild: the stored provisional entries, updated or added from Bandai's list for each code `sets.json` lacks. An entry Bandai no longer lists stays; a code in `sets.json` is never in the result (so Bandai's version of a reviewed set is recorded nowhere, also when the owner promoted a code that was provisional). The refresh passes only Bandai's card packages (with a package id), as today; `sync` and `reparse` pass every set they build, as they used to put every one into `sets.json`.
- `reviewed_set_notes(tracked, bandai)`: one informational line per reviewed set missing from Bandai's list (`reviewed set PB03 is not on Bandai's list`) or differing from it (`reviewed set GD01 differs from Bandai: name, release date`; the fields compared are name, kind, release date, package id, category, url). Printed by `sync`, `reparse` (and so `refetch`) and in the refresh report; it changes no exit code and writes nothing.

The CLI's `_save_sets` becomes `_record_sets`: it writes `provisional_sets.json` in the dataset (only when its content changed, as `write_provisional_sets` does) and prints the count, the notes and the parse issues as before. `reparse` then takes its release dates from `load_sets()` (the `sets.json` entry wins, provisional sets fill the rest), no longer from the rebuilt list. `kind_for_code` maps the `PB` prefix to `promo`. With no tracked `sets.json` every set is proposed as provisional and no tracked file is created; `sets` then says on stderr that there is no tracked set list and lists the provisional sets (exit 0), or, with neither, says so and exits 2.

Why this over the obvious alternative (keep writing `sets.json`, but merge instead of overwrite): any tool write to the reviewed file can revert or drop a hand edit; with no writer at all, AC-3's byte-identical guarantee holds by construction, and the provisional record (already read everywhere through `load_sets`) carries what is new.

**Cleanup from the spec's notes.** A new rule `.claude/rules/data-folders.md`: data folders are resolved when a function runs, never at import or as default argument values. `docs/testing.md` gains the env var and a stated exception: a test may read `docs/catalog-export.md` to check the contract against its fixture. `test_every_subcommand_of_the_other_tools_is_run_above` is removed from `shared/test_read_commands_on_dataset.py`; the "no other command writes the export" test stays, no longer claiming to cover every command.

## Files and interfaces
- `shared/basetypes.py`: `CardNumber` `[A-Z]+[0-9]*-[0-9]{3}`, `PrintingId` `[A-Z]+[0-9]*-[0-9]{3}(?:_p[0-9]+)?`, `PackageId` `[0-9]+`.
- `docs/identifier-examples.json`: invalid non-ASCII digit cases for card number (after the set letters, in the three-digit part), printing id (also in the `_p` number) and set code.
- `shared/dataset.py`: `TOOL_DATA_VAR = "GCG_TOOL_DATA_DIR"`, `REPO_ROOT`, `tool_data_root() -> Path`; `RealDataWrite`, `refuse_real_data_write(path: Path) -> None`, called by `write_atomic` here, in the cards and meta stores and in `shared/fetch.py`'s cache write.
- `tools/gundam_cards/store.py`: `raw_folder() -> Path`, `tracked_folder() -> Path` replace `RAW_DIR`, `OUT_DIR`, `REPO_ROOT`; `load_source_pages(raw_dir=None, ...)`, `load_tracked_sets(out_dir=None)`, `load_sets(out_dir=None, data_out=None)`, `raw_dump_stamps(raw_dir=None)`, `read_raw_dump(stamp, raw_dir=None)`, `write_restrictions(file, out_dir=None)`, `load_restrictions(out_dir=None)`; `write_sets` removed.
- `tools/gundam_meta/store.py`: `raw_folder()`, `tracked_folder()` replace `RAW_DIR`, `OUT_DIR`, `REPO_ROOT`; `write_popularity(popularity, out_dir=None)`.
- `tools/gundam_cards/sets.py`: `propose_sets(tracked, stored, bandai) -> tuple[CardSet, ...]`, `reviewed_set_notes(tracked, bandai) -> tuple[str, ...]`; `PB` -> `SetKind.PROMO`.
- `tools/gundam_cards/refresh.py`: `refresh_catalog(..., tracked_dir: Path | None = None, ...)`; uses `propose_sets`; `RefreshReport.reviewed_notes`, printed by `format_report`.
- `tools/gundam_cards/cli.py`, `tools/gundam_meta/cli.py`: folders from the functions at run time; `_record_sets`; `reparse` dates from `load_sets()`; `sets` without a tracked list.
- `conftest.py`: `GCG_TOOL_DATA_DIR` per test (and per session, for collection-time skips), seeded with the tracked `sets.json` and `restrictions.json`.
- `.claude/rules/data-folders.md` (new); `docs/testing.md` (the exception, the setting, the backstop, `GCG_TEST_REAL_DATA=1` only deliberately and never on an old or base checkout); `docs/commands.md`; `docs/glossary.md` (provisional package); `.claude/CLAUDE.md` (the setting); `tools/gundam_cards/design.md`, `tools/gundam_meta/design.md` (folders, `sets.json` only by hand).
- Tests: `shared/test_identifier_examples.py`, `shared/test_basetypes.py`, `shared/test_tool_data_dir.py` (new), `shared/test_real_data_guard.py` (new), `tools/gundam_cards/tests/test_reviewed_sets.py` (new); existing tests that patched `RAW_DIR`/`OUT_DIR`/`write_sets` updated.

## Tests
- AC-1 (`shared/test_identifier_examples.py`): the identifier table of `docs/catalog-export.md` is read and each pattern taken; every valid example of `docs/identifier-examples.json` fully matches both the documented pattern and the toolkit type, every invalid one matches neither; the fixture's invalid lists hold the non-ASCII digit cases. `shared/test_basetypes.py`: `PackageId` accepts `616105` and rejects `６１６１０５` and `٦١٦١٠٥`.
- AC-2 (`shared/test_tool_data_dir.py`): with `GCG_TOOL_DATA_DIR` and `GCG_DATA_DIR` at temp folders, a few saved fixture pages (detail pages and a package listing, plus a set list) are put in the temp raw folder and `gundam_cards reparse` runs through `main` (real parsers and writers): the catalog and provisional record land in the temp dataset, `sets` lists the temp tracked file's sets, and the real tracked `sets.json` and `restrictions.json` are byte-identical and the real raw folder's files (names, sizes, modification times) unchanged. Also `gundam_meta popularity` writes `popularity.json` into the temp tracked folder and the real one is unchanged. With the variable unset the folders are the repository's (`tools/<tool>/data/raw`, `shared/data/<tool>`).
- AC-2 backstop (`shared/test_real_data_guard.py`): `HOME` points at a temp folder (so `~/.gcg` resolves there and the real one is never touched) and `GCG_DATA_DIR`/`GCG_CATALOG_FILE` are unset, as a forgetful test leaves them. Each store writer refuses a path in the dataset, the catalog export, an images folder and `~/.gcg` itself with `RealDataWrite` and a clear message; `write_catalog` and `write_event` at their default dataset are refused; the fetcher refuses to cache under `~/.gcg/images`; nothing appears under the temp home; a write outside `~/.gcg` still works.
- AC-3 (`tools/gundam_cards/tests/test_reviewed_sets.py`): a tracked `sets.json` with GD01 (its data differing from Bandai's) and PB03 (not on Bandai's list); Bandai lists GD01, a new GD09 and a new PB04. For `reparse` (saved pages), `sync --only sets` and `sync` (fake Bandai fetcher), and `refresh` (fake Bandai): `sets.json` byte-identical, the two report lines printed, exit code 0 (as with a matching list), GD09 in `provisional_sets.json` as a booster and PB04 as promo, GD01 not recorded there. A later rebuild updates a provisional entry and keeps one Bandai no longer lists. Release dates for the rebuilt catalog come from `sets.json` (a card's text-version `as_of` is the tracked GD01 date, not Bandai's). The export still builds with PB03 kept. With no tracked `sets.json`: every set proposed, no file created, `sets` says there is no tracked set list and lists the provisional sets.

## Risks
- The backstop recognizes a test run by `pytest` being imported. A test run by another runner would not be guarded (none is used here). It guards `Path.home() / ".gcg"` as resolved at the write; a test that points `HOME` elsewhere moves it with it, which is what the guard's own test relies on.
- Seeding the per-test tool folder with the real tracked files keeps today's tests that read them working, but means those tests still depend on that content (they did before); a test that needs a specific set list writes its own into the temp folder.
- `sync`/`reparse` now print one line per reviewed set that differs from Bandai; for hand-edited entries (PB01-PB03 as promo, names) the lines repeat every run. They are informational by the spec's design.
- Proposing every built set (not only card packages) from `sync`/`reparse` may record product-only codes as provisional; this is what `sync` already put into `sets.json`, now kept out of the reviewed file.
