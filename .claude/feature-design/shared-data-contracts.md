# shared-data-contracts: design

Spec: `claude-workspace/specs/gcg-toolkit/shared-data-contracts/spec.md` (PersonalClaude workspace)

## Approach
A new command, `gundam_cards export`, is the only writer of the catalog export. It reads the stored catalog (`cards.json`), the tracked `sets.json`, the dataset's provisional sets and every stored price snapshot, hands them to one pure function, `export.build_export`, and writes the result atomically (`store.write_atomic`: a temp file in the same folder, renamed over the old one) to `$GCG_CATALOG_FILE`, or `~/.gcg/catalog.json` when it is unset. With no catalog it says "no data: card catalog" and exits 2, like every reader. With no price snapshot it still writes (printings simply carry no price) and says "no data: prices" on stderr.

**The export model.** Frozen pydantic models in `tools/gundam_cards/export.py`: `CatalogExport` (`schema_version` 1, `generated_at`, `reference`, `cards`), `ExportCard`, `ExportPrinting`, `ExportReference`, `ExportSet`, `ExportKind`. Fields that may not apply are optional and default to `None`, and the file is written with `exclude_none`, so it never holds a `null`; flags that are present only when true (`no_longer_listed`, `provisional`) are typed `Literal[True] | None`. A card carries `number`, `name`, `kind`, `no_longer_listed` (when true), `set_code` (its first printing's, when it has one), `color`/`level`/`cost` (deck kinds only, via the existing `color_of`/`level_of`/`cost_of`), and its printings in catalog order. A printing carries `id`, `rarity`, `set_code` (when known), and on a non-base printing (one with a `_pN` variant) `variant`, `alt_art_level` and `link_art`; `image_url` when known; `price_cents` and `price_as_of` (a date) when the store has a price for it. Cards in the catalog marked no longer listed are kept and flagged, so the export has exactly one entry per catalog card.

**Prices per printing, from what the store holds.** The store keeps one price row per *card* (the cheapest non-alt-art, non-promo TCGPlayer product; `CardPrice`), with that product's TCGPlayer set abbreviation; per-printing prices arrive with `refresh-prices`. Nothing in the store says which printing that product is, so the export matches a row to a printing only when exactly one printing of the card is not an alt art (`alt_art_level == 0` and not `link_art`) and has the row's set code. No match or several matches: no printing gets that row (never guessed). The price of a printing is its matched row from the newest snapshot that has one ("the latest price for that printing in the store"); its as-of date is that row's `fetched_at` date (UTC). On the real dataset this prices 1013 of 1032 priced cards' printings. When `refresh-prices` lands, only this matching changes.

**Reference.** Built from the toolkit's own data, never typed out: `sets` is the tracked `sets.json` plus the provisional sets (a code in both: the tracked entry wins, as `store.load_sets`), each with code, name, kind, `release_date` when known, and `provisional: true` for a provisional one (its name is Bandai's, as the refresh records it); `kinds` is every `CardKind` with `deck` from `CardKind.is_deck_card`; `colors` and `rarities` are the `Color` and `Rarity` vocabularies. Before anything is written, every set code on a printing (the card's set code is its first printing's) is checked against `reference.sets`; missing codes raise `MissingSetCodes`, the command prints them and exits 1, and no file is written.

**The contract document.** `docs/catalog-export.md` defines the identifier shapes (card number, printing id, set code) once, documents every field, the version policy and the location, and points at two files beside it for other apps to reuse as test fixtures: `docs/catalog-export.example.json` (a valid example export) and `docs/identifier-examples.json` (valid and invalid identifiers per kind). Tests read both: the example must validate as a `CatalogExport` and hold no `null`, and the toolkit's `CardNumber`, `PrintingId` and `SetCode` must accept exactly the valid ones and reject the invalid ones.

Why this over writing the export from the existing models (`CardsFile.model_dump`): the stored card carries text, stats, traits and FAQ, which the spec excludes, and has `null`s; an explicit export model makes the contract visible and keeps it stable when the store changes.

## Files and interfaces
- `tools/gundam_cards/export.py` (new, pure): `EXPORT_SCHEMA_VERSION = 1`; the models above; `MissingSetCodes(Exception)` with `codes: tuple[SetCode, ...]`; `build_export(catalog: CardsFile, tracked_sets: tuple[CardSet, ...], provisional_sets: tuple[CardSet, ...], price_history: tuple[PriceFile, ...], generated_at: datetime) -> CatalogExport`; `printing_prices(card, price_history) -> dict[PrintingId, tuple[int, date]]`; `export_json(export: CatalogExport) -> str` (indented, no nulls).
- `tools/gundam_cards/store.py`: `CATALOG_FILE_VAR = "GCG_CATALOG_FILE"`; `catalog_export_path() -> Path`; `load_price_history(out_dir=None) -> tuple[PriceFile, ...]` (oldest first); `write_catalog_export(export: CatalogExport, path: Path) -> None`.
- `tools/gundam_cards/cli.py`: `export` subcommand (`cmd_export`). Exit 0 written, 1 missing set codes (nothing written), 2 no catalog.
- `conftest.py`: every test gets `GCG_CATALOG_FILE` pointed at a temp file, so no test can write `~/.gcg/catalog.json`.
- `shared/test_empty_dataset.py`: `export` listed as a reader whose other source is prices (exit 0).
- `docs/catalog-export.md`, `docs/catalog-export.example.json`, `docs/identifier-examples.json` (new).
- Docs: `docs/commands.md` (the command), `docs/glossary.md` (catalog export), `tools/gundam_cards/design.md` (Outputs).

## Tests
- AC-1 (`tools/gundam_cards/tests/test_export.py`, through `cli.main(["export"])` on a small catalog written to the temp dataset): exit 0; the file at `$GCG_CATALOG_FILE` has `schema_version` 1, a `generated_at`, a `reference`, one card per catalog card in number order, each card's printings nested under it in catalog order, with number, name, kind, printing id and rarity; a card marked no longer listed is included with `no_longer_listed: true` and the others have no such key. With `GCG_CATALOG_FILE` unset the path is `~/.gcg/catalog.json` (checked with `HOME` pointed at a temp folder). A failed write (the rename raises) leaves an earlier export byte-identical and no temp file. The only-writer rule is met by the code (only `cmd_export` calls `write_catalog_export`) and judged by review.
- AC-2: the whole file holds no `null` (walked recursively); a unit has color, level and cost and a resource or token has none; the card's set code is its first printing's, and a card whose first printing has none has no `set_code`; a base printing has no variant, alt-art level or link-art keys but has its set code; an alt-art printing has all three and its image URL; a printing with no image URL has no `image_url`; a card's price row matches its one non-alt printing in that set and gives `price_cents` and `price_as_of` (date only), the newest snapshot winning and an older snapshot's price kept for a printing the newest has none for; an alt art, a printing in another set, and a card with two non-alt printings in the price's set get no price; no card-level price, and no text, stats, traits or keywords keys appear anywhere. Expected values are worked out by hand from the fixture.
- AC-3: `reference.sets` lists the tracked sets and a provisional one flagged `provisional: true` with its (Bandai) name, a tracked entry winning over a provisional one with the same code, `release_date` absent when unknown; `reference.kinds` is all eight kinds with deck true for exactly unit, pilot, command, base; `colors` and `rarities` equal the toolkit's vocabularies. A printing whose set code is in neither list makes `export` exit 1, name the code on stderr, and leave no file (and an earlier export byte-identical).
- AC-4 (`shared/test_identifier_examples.py`): for each kind in `docs/identifier-examples.json`, the toolkit's type accepts every valid value and rejects every invalid one, and the list contains the spec's examples. `tools/gundam_cards/tests/test_export.py`: `docs/catalog-export.example.json` validates as a `CatalogExport` and holds no `null`. The schema document itself is checked by review.
- No data: `export` on an empty dataset says "no data: card catalog" and exits 2; with a catalog and no prices it writes and says "no data: prices" (`shared/test_empty_dataset.py`).

## Risks
- **Prices are matched to printings by set code (spec interpretation).** The spec asks for "the latest price for that printing in the store", while the store holds one price per card until `refresh-prices`. The export attributes a card's row to its single non-alt printing in the row's TCGPlayer set and otherwise gives no price; TCGPlayer abbreviations that differ from Bandai's set codes (`GD01_b`) or printings with no set code never match. On the real dataset 1013 of 1032 rows match one printing, 10 match two (no price), 9 match none. If the owner meant "put the card's price on its base printing", only `printing_prices` changes.
- **The real dataset fails the set-code check today.** Printings of the 1st Anniversary Set carry set code `PB03`, which is neither in `sets.json` nor in the provisional sets, so `export` on the real data exits 1 naming `PB03` until that set is added (by review into `sets.json`, or a refresh recording it as provisional). This is the spec's intended behavior (AC-3), not a bug in the export.
- **gcg-toolkit#5 (two Bandai products share a set code).** `build_sets` keeps one set per code (the first product's name, release date and link; the second product is skipped with a `parse_failure` warning), and the tracked and provisional lists are keyed by code with the tracked entry winning, so a shared code still appears exactly once in `reference.sets`. The export therefore does **not** fail on #5: the code exists, and the set carries the first product's name and release date, which may be the wrong product's. The export cannot detect this; #5 stays open and is unchanged by this slice.
- **Colors and rarities are the full vocabularies**, not only the values found on cards ("in use (the toolkit's own vocabularies)"); a new color or rarity would already fail the catalog parse, so the two never differ in practice.
- **Reading every price snapshot** grows with history (one file per day at most). Fine at today's size; `refresh-prices` may add a cheaper "latest per printing" read.
